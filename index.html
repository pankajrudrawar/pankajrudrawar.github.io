How the modules are built

Storage is long-lived and expensive to get wrong, so the modules favor settings that are safe on the first apply and easy to change later.

Secure defaults

Encryption on, public access off, TLS enforced. Anything riskier needs an explicit input.

Maps instead of lists

Mount targets, volumes and rules are keyed maps. Adding or removing one entry never reshuffles the others.

# keys stay stable, so plans stay small
mount_targets = {
  az1 = { subnet_id = "subnet-0a1" }
  az2 = { subnet_id = "subnet-0b2" }
}

Secrets stay separate

Passwords are their own sensitive variables, so the rest of each object remains readable in plans and reviews.

Checked on every push

GitHub Actions runs terraform fmt, validate and TFLint for the module and its example. Pre-commit hooks keep the docs in sync.
